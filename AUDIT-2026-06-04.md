# Post-deploy audit — 2026-06-04

Five issues raised after the chain-626 mainnet deploy + handoff. Each section
covers the finding, the action taken, and the on-chain receipts where
applicable.

## 1. Chain 626 Governance was deployer-owned, no transfer initiated

**Finding.** `Chain 626 Governance` (`0x9d1c800574557dBFE23A15eBefb40207a38d33cf`,
the per-chain Governance contract deployed by `RegisterZKChain.deployGovernance`)
was still `owner = deployer`, `pendingOwner = 0`. The earlier handoff covered
the chain admin but not this contract.

**Action.** Deployer called `transferOwnership(0xc177aC25…58f3)` so the
per-chain Governance lines up with the chain admin destination.

**State now.** `owner = 0xA41a… (deployer)`, `pendingOwner = 0xc177aC25…`. The
real chain admin must call `acceptOwnership()` to finalize.

**Tx.**
- transferOwnership → https://etherscan.io/tx/0x5b926c068dcdf32f5bcc5f530786535c2240ebe749b793845be99206d30afc8c

## 2. CTM admin role was unset (0x0)

**Finding.** `ChainTypeManager` (`0x4Ee4EA87b909ea3E1C36d9fcbf6C0e535165f96D`)
has its own `admin` role distinct from `owner`. The deploy script *had* called
`ctm.setPendingAdmin(ecosystemChainAdmin)` during step 3, but the corresponding
`acceptAdmin()` was never executed, so `CTM.admin()` returned `0x0`.

**Action.** Routed via Governance →
`EcosystemChainAdmin.multicall([{CTM, 0, acceptAdmin()}], true)`.
The ChainAdmin (now Governance-owned since the 2026-06-03 ownership re-routing)
holds the pending admin role and accepted it.

**State now.** `CTM.admin() = 0xbc8e06ABa0ef1cE015A5d9207b61B470D751404b` (= ecosystem ChainAdmin).

**Tx.** Bundled with #5 below (one `governance.execute` carrying 3 sub-calls):
- schedule → https://etherscan.io/tx/0x8a80f916eaa7b83be56da13d0df6245c10d0a7302ba5b39aa0f8e6b5c40c1b32
- execute  → https://etherscan.io/tx/0x563a995f004ae9e0ea0f8ea6cf30901a35e0f1a289e5c8f9e9a26eaa89631ae1

## 3. ServerNotifier uses a separate ProxyAdmin owned by ecosystem ChainAdmin

**Finding.** Every ecosystem proxy uses the main ProxyAdmin
(`0x31b477779cfdf178b618c0517d75ab42fcbef691`, Governance-owned) **except**
`ServerNotifier` (`0x3AB68bf9Dd6964650a98F1254aAC39B6B1ba2E80`), which uses
`0x336a2d234b2f1d195f68faaa129584097d0c5c34` — owned by the ecosystem
ChainAdmin, not Governance. The ServerNotifier proxy's own `owner()` is also
the ecosystem ChainAdmin.

**Action.** None. **Intentional by design.** `DeployCTM.s.sol` deploys a
dedicated ProxyAdmin owned by the ecosystem ChainAdmin:

```solidity
address ecosystemProxyAdmin = deployWithCreate2AndOwner("ProxyAdmin", addresses.chainAdmin, false);
…
deployTuppWithContractAndProxyAdmin("ServerNotifier", ecosystemProxyAdmin, false);
…
IOwnable(addresses.stateTransition.serverNotifierProxy).transferOwnership(addresses.chainAdmin);
```

`ServerNotifier` handles server-side notifications for chain
migration to/from gateway — operational, not governance-level — so it lives
under the ChainAdmin (faster operational admin) rather than Governance
(slower deliberative governance).

**State now.** Documented in `DEPLOYED-ADDRESSES.md` under "Proxy admins".

## 5. RollupDAManager whitelist pointed at the orphaned validator

**Finding.** The deploy-time `RDM.updateDAPair(0x3E976F63…, 4, true)` call
[0x57978b4c…](https://etherscan.io/tx/0x57978b4c0dfbe0f2b0a97aecef0a8fc0be09a2ef4b85c79c6cab242a00c6d451)
whitelisted the **initial unoptimized** BlobsL1DAValidatorZKsyncOS
(`0x3E976F63373059C4CeBEad1dee0dEF4866018E4d`). After we replaced it with the
optimized canonical-matching `0x3368766f6d565f14eA0cFd71236999d6c93fbDbE` on
2026-06-02, the live validator was *not* whitelisted in the RollupDAManager.
This would have blocked any future `makePermanentRollup()` call on chain 626.

**Action.** Two `updateDAPair` calls bundled into a Governance operation:
- `updateDAPair(0x3368…fbDbE, 4, true)` — whitelist the live validator
- `updateDAPair(0x3E976F63…, 4, false)` — un-whitelist the orphan

**State now.**
- `RDM.isPairAllowed(0x3368…fbDbE, 4) == true` ✅
- `RDM.isPairAllowed(0x3E976F63…, 4) == false` ✅

**Tx.** Same bundled `governance.execute` as #2 above:
- schedule → https://etherscan.io/tx/0x8a80f916eaa7b83be56da13d0df6245c10d0a7302ba5b39aa0f8e6b5c40c1b32
- execute  → https://etherscan.io/tx/0x563a995f004ae9e0ea0f8ea6cf30901a35e0f1a289e5c8f9e9a26eaa89631ae1
